# Модули 3 и 4: гибридный поиск и реранк

Рабочий репозиторий для двух модулей юридического RAG-ассистента ПСБ:
**Hybrid RAG (BM25 + векторы + RRF)** и **Reranker**. Здесь только эти модули и
всё, что им нужно; решение для платформы хакатона живёт отдельно и сюда не
копируется.

## Что внутри

| Файл | Роль |
|---|---|
| `search.py` | лексический поиск BM25 (`rank-bm25`) |
| `vector_index.py` | матрица эмбеддингов и поиск по косинусу |
| `hybrid.py` | слияние RRF, реранк с деградацией (`/rerank` → LLM → порядок RRF) |
| `refs.py` | формат ссылки: «п. 3.1», «НК РФ, ст. 164» |
| `contract_adapter.py` | внутренние объекты → JSON контракта v1.1 (`RetrievedCandidate`, `RerankedChunk`) |
| `check_contract.py` | 107 проверок контракта на реальной базе, пишет фикстуры |
| `prepare_chunks.py` | собирает фрагменты из `data/knowledge-base.zip` без сети |
| `chunking.py`, `ingest.py`, `textproc.py` | нарезка и токенизация (смежная зона, не менять без согласования) |
| `config.py` | все параметры поиска и пороги |
| `docs/CONTRACTS-ALL.md` | согласуемый контракт модулей, v1.0-draft |
| `docs/MODULE_3_4_REVIEW.md` | разбор: где схема, контракт и код расходятся; что править в v1.1 |

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows;  source .venv/bin/activate — Linux/WSL
pip install -r requirements.txt

python prepare_chunks.py        # ZIP → artifacts/chunks.jsonl, без сети
python check_contract.py        # 107 проверок, пишет data/fixtures/
```

Ожидаемый вывод последней команды:

```
ИТОГ: пройдено 107, провалено 0
Фикстуры записаны в data/fixtures/ (4 файла)
```

## Границы ответственности

**Мои модули (3 и 4):** поиск, слияние, реранк, поля кандидата, метрики
достаточности (`stats`).

**Не моё и не правится здесь:** генерация ответа и верификация (модуль 5),
API и маршрутизация (модуль 1), анализ вопроса и переформулировка (модуль 2),
индексация (модуль 6).

Контракт — единственная точка стыковки. Если нужного поля нет в контракте,
сначала правим `docs/CONTRACTS-ALL.md`, потом код: иначе у каждого модуля
появится свой формат.

## Три вопроса, которые надо закрыть командой

Подробно — в `docs/MODULE_3_4_REVIEW.md`, §6.

1. Кто владеет решением о достаточности контекста: модуль 3, модуль 4 или пайплайн?
2. Кто крутит цикл повторного поиска: переформулировка — модуль 2, цикл — пайплайн?
3. Мультизапросность (`search_queries`, 1–3 формулировки): делаем или убираем из контракта?

## Клиенты моделей

`hybrid.py` работает без сети: если клиента нет, поиск идёт на одном BM25.
С ключом в `.env` подключаются эмбеддинги и `/rerank`. `.env` в git не попадает
(см. `.gitignore`).
