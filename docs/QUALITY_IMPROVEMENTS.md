# Изменения после первого платформенного результата

Исходный результат пользователя: 18,152/100. Детализация по вопросам и трасса
платформенного запуска недоступны; причины нельзя установить по одному числу.
Исправлены обнаруженные ограничения реализации:

- CSV-диалоги разделяются на последнюю реплику и историю. Предыдущий ответ
  ассистента не считается источником юридических фактов.
- Стеммер согласует падежные формы. Раньше «согласование», «согласования»
  и «согласованию» превращались в разные основы.
- Без векторов BM25 сохраняет всю выдачу, вместо ограничения глубиной слияния.
- Формулировки объединяются по ID, затем ранжируются один раз. Дополнительный
  поиск по содержанию уменьшает влияние повторяющихся реквизитов.
- Контекст включает соседние пункты, допсоглашения и альтернативные редакции.
  Явные даты вступления и отмены передаются вместе с положением.
- Внедрённая в записку команда про 90 дней не передаётся модели.
- Модель использует короткие ID, код восстанавливает и проверяет исходные.
  Исправляемый черновик передаётся повторной генерации вместе с причиной.
- JSON в Markdown-ограждении принимается, повторяющиеся ключи отклоняются.
- Удалён ошибочный жёсткий предел 150 слов; сохранён предел 10 000 символов.
- Временные API-ошибки повторяются; готовые ответы сохраняются по мере выполнения.
- ZIP строится по графу импортов и содержит отдельный verify_submission.py.

## Демо и границы проверки

18 вопросов и 18 ответов организаторов. Из ответов вручную размечены 22 нужных
положения для 17 отвечаемых вопросов. Вопрос о пособии не имеет ответа в этом
корпусе и исключён из метрики покрытия.

| Режим без LLM и векторов | Нужные положения в контексте | Полностью покрыто вопросов |
|---|---:|---:|
| Исходный контекст | 18/22 | 14/17 |
| Новые первые 6 фрагментов | 16/22 | 11/17 |
| Новый контекст с расширением | 22/22 | 17/17 |

Сравнение включает изменение бюджета и состава контекста. Это покрытие
доказательств, а не сравнение Recall@6 и не оценка юридического ответа.
Ранжирование первых шести в чисто лексическом режиме не улучшилось: прирост
полноты обеспечен расширением контекста. Работа с реальными векторами,
реранкером и генератором требует следующего платформенного прогона.
Демо используются как регрессионная проверка; скрытый набор неизвестен.

Исходная трасса и прежний ZIP сохранены в artifacts/score_baseline/.
Команда воспроизведения:

    python3.12 tools/benchmark_retrieval.py --baseline artifacts/score_baseline/retrieval.json

Распакованный ZIP проверяется в пустом каталоге с HTTP-подменой LLM и
эмбеддингов: CSV, порядок ID, JSONL и повторная проверка источников.
Тестовый API подтверждает интеграцию и формат, но не качество реальной модели.
Живой прогон LLM не выполнен: локальная конфигурация не содержит корректного
адреса API. Новый платформенный балл станет известен после отправки ZIP.
