# ПСБ: юридический ИИ-ассистент

Веб-чат и пакетный запуск используют общий движок `platform_solution`: поиск BM25 и по эмбеддингам, реранжирование, контекст связанных документов, генерацию и проверку чисел и ссылок. При ошибке основного ответа доступен резервный путь из модулей подготовки запроса, поиска и проверенной генерации. Он включается только при сбое и возвращает ответ, если проверка его подтвердила. Успешный ответ платформенного движка резервом не заменяется.

Результат зависит от базы знаний, настроек модели и доступности внешнего API. Совпадение движка не гарантирует одинаковые ответы недетерминированной модели или высокий балл платформы: это проверяется отдельным прогоном на платформе.

## Запуск

Скопируйте `.env.example` в `.env` и заполните `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, а при наличии реранкера — `RERANKER_MODEL`. Файл `.env` не включается в образ или архив. База находится в `data/knowledge-base.zip`; после её замены пересоберите образы.

```bash
cp .env.example .env
make dev
```

- Интерфейс: http://localhost:8000
- API в режиме разработки: http://localhost:8001/api/health
- Dozzle в режиме разработки: http://localhost:9999
- Логи и остановка: `make dev-logs`, `make dev-down`

Dozzle подключён к Docker socket и доступен по умолчанию только с локального компьютера. Не открывайте его в интернет. Порты API и Dozzle можно изменить через `BACKEND_PORT` и `DOZZLE_PORT`; адреса привязки — через `BACKEND_BIND` и `DOZZLE_BIND`.

Production:

```bash
make prod
make prod-logs
make prod-down
```

В production публикуется только frontend (`FRONTEND_PORT=8000`, `FRONTEND_BIND=0.0.0.0` по умолчанию). Backend доступен frontend внутри сети Compose, Dozzle не запускается. Команды остановки не удаляют том с историей. Профили используют один проект Compose; `make dev` и `make prod` переключают состав сервисов.

Другие команды: `make help`, `make build`, `make config` (проверка обеих конфигураций), `make test`, `make benchmark`. Без Docker установите зависимости из `requirements.txt` и `platform_solution/requirements.txt`, затем запустите `make web`.

## Запуск на платформе

```bash
make submit
# dist/psb_hack_change_submission.zip
```

Архив содержит только Python-файлы и `requirements.txt` в корне. Он включает общий движок и модули резервного пути, без `.env`, базы знаний и демонстрационных ответов. Платформа предоставляет `DATA_DIR/questions.csv` (`id,question`), архив базы и переменные API; результат сохраняется в `submission.csv`, трасса — в `answer_trace.jsonl`. CSV обновляется после каждого завершённого вопроса. `SOLUTION_TIME_BUDGET` задаёт бюджет в секундах (по умолчанию 1080), `SOLUTION_WORKERS` или `MAX_WORKERS` — параллельность. `ANSWER_TRACE=0` отключает трассу.

Для локального прогона:

```bash
python solution.py --questions data/demo_questions.csv \
  --out artifacts/demo/submission.csv --trace artifacts/demo/answer_trace.jsonl
```

Без настроенного LLM отображаются извлечённые положения документов. `make platform-zip` отдельно собирает исходный монолитный вариант для сравнения. `make benchmark` измеряет покрытие источников модульным поиском на демо, а не балл платформы.

## Устройство

- `API/app.py`, `API/engine.py`, `API/batch.py` — HTTP, общий движок и пакетный запуск.
- `platform_solution/solution.py` — основной платформенный поиск и генерация.
- `API/fallback.py`, `query_processing_module/`, `data_processing/`, `rag_pipeline/`, `answer_generation/` — резервная обработка, поиск и проверка.
- `compose.yaml`, `compose.dev.yaml`, `compose.prod.yaml`, `deploy/` — конфигурации окружений.

Диалоги сохраняются в SQLite и отображаются в боковой панели отдельно для каждого из трёх демонстрационных пользователей. Кнопка «Новый диалог» не удаляет предыдущие переписки; первая отправка сохраняет новый диалог. Старые записи автоматически переносятся в историю профиля. В Docker база находится в томе `assistant-data` и сохраняется при обычной остановке контейнеров. Это демонстрационный интерфейс без настоящей аутентификации. Проверка LLM и ссылки на источники не являются гарантией юридической корректности.
